Technical Architecture
Browser-Direct

Credly — CORS-open JSON API

Credly exposes a public endpoint at credly.com/badges/{uuid}.json with proper CORS headers. The browser calls it directly — no proxy needed. Returns full badge metadata including skills, image, issue & expiry dates. Invalid UUIDs return 404 which is caught.

Server Proxy

6 platforms — Supabase Edge Function

Coursera, Udemy, Accredible, edX, freeCodeCamp, Kaggle all block cross-origin browser fetches. Our Deno edge function (verify-cert) runs server-side, fetches the public certificate page, extracts JSON-LD structured data (application/ld+json), and returns parsed metadata. verify_jwt: false — no auth required.

Regex Patterns

10 platforms — URL validation only

Platforms with no accessible public API. We test the URL against 19 regex patterns. Match → url_valid status (+5 pts). No external calls made. Patterns are precise enough to reject fabricated URLs that don't match the issuer's format.

PDF Scanner

Zero-friction PDF auto-extraction

User drops their certificate PDF. pdfjs-dist extracts all text across every page and scans with 19 regex patterns. If no URL found in text, each page is rendered to canvas at 2× and scanned with jsQR for embedded QR codes. URL auto-fills the form.

PDF Auto-Extraction — How It Works
📄

User drops PDF — we find the URL automatically

Most certificate platforms embed the verification URL either as visible text or as a QR code inside the PDF. We scan both — no manual copy-paste from a PDF ever required.

1

Text extraction — every page is scanned for URL patterns matching all 19 supported platforms (Credly, Coursera, Udemy, LinkedIn, Accredible, Microsoft, OpenCerts, edX, freeCodeCamp, Kaggle, DataCamp, Salesforce, Pluralsight, HubSpot, Codecademy, Google, Duolingo…)

2

QR code scan — if no URL found in text, each page is rendered to canvas at 2× resolution and scanned with jsQR. QR URL is extracted and matched against the same 19 patterns.

3

Auto-fill & verify — extracted URL populates the credential URL field. Platform is detected, logo loads, issuer dropdown auto-selects. User confirms the name and clicks Verify & Add →

UX Features Implemented
🏷️

Platform auto-detection + real logos (Clearbit)

As the user types or pastes a URL, the platform is detected instantly from the URL pattern. The real company logo is fetched from Clearbit Logo API (logo.clearbit.com/{domain}) and displayed in the platform pill, the credential card, and the modal. If Clearbit fails for any reason, falls back gracefully to an emoji icon.

📋

Smart issuer dropdown — no free-text typing

Issuer field is a dropdown pre-populated with the known issuers for the detected platform (e.g. Credly → "Amazon Web Services", "Google Cloud", "Cisco", "CompTIA"…). Single-issuer platforms (Udemy, LinkedIn Learning, HubSpot, Duolingo…) auto-select without requiring any user action. "Other…" escape hatch reveals a free-text input for anything not in the list.

🔄

Re-verify from credential card

Credentials saved as url_valid (added offline, or verification failed transiently) show a "Verify now →" button on the card. One click re-runs full verification against the live issuer. Status upgrades from URL valid (+5 pts) to Verified (+15 pts), immediately boosting the Trust Score.

🛡️

Invalid certificate detection & rejection

Fake or invalid certificate IDs are caught server-side. Coursera example: invalid cert IDs redirect to Coursera's homepage (200 response, wrong URL). Our edge function checks the final URL after fetch — if redirected away from the expected cert URL pattern, it throws "Certificate not found." The user cannot save a fake credential as Verified.

📶

Offline-graceful error handling

Network errors (transient failures, CORS) do not block the user. The credential saves as url_valid if the URL pattern matches, or manual if not. Non-network errors from the issuer (invalid cert, platform rejects) show a red error message and block saving. This prevents bad data while being friendly to poor connectivity.

Known Limitations & Roadmap
⚠️

LinkedIn Learning — no public API

LinkedIn uses a closed B2B push integration where partner platforms push completion data to LinkedIn via OAuth. There is no publicly accessible reverse verification endpoint. URL pattern check only. Future option: accept LinkedIn profile export PDF and parse the certificates section.

⚠️

OpenCerts — blockchain verification not yet implemented

OpenCerts uses W3C Verifiable Credentials anchored on a Singapore government blockchain. Full verification requires on-chain lookup via the OpenCerts SDK. Currently URL-validated only. High impact for Singapore academic institutions (NUS, NTU, SMU, SP) — on the roadmap.

⚠️

Scrape-based platforms may break if issuers change their HTML

Coursera, Udemy, edX, freeCodeCamp, Kaggle are verified by scraping public certificate pages and extracting JSON-LD structured data. If issuers change their HTML schema, metadata extraction fails and the credential falls back to url_valid status until the edge function is updated. This is a maintenance overhead that needs monitoring.
